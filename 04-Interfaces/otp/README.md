# otp

Реализуйте две обёртки над потоками. Каждый байт данных преобразуется с помощью
XOR с очередным байтом из второго потока `prng`:

```go
func NewReader(r io.Reader, prng io.Reader) io.Reader
func NewWriter(w io.Writer, prng io.Reader) io.Writer
```

- `NewReader` возвращает Reader: он читает из `r`, преобразует прочитанные байты
  и отдаёт их вызывающему коду.
- `NewWriter` возвращает Writer: он преобразует переданные байты и записывает
  результат в `w`.

Обе обёртки должны работать с любыми реализациями соответствующих интерфейсов.
Генерировать случайные числа самостоятельно не нужно: поток `prng` уже передан.

## Как работает преобразование

`byte` — целое число от 0 до 255. Оператор `^` выполняет побитовый XOR:

```go
byte(65) ^ byte(42) // 107
byte(107) ^ byte(42) // 65
```

Для данных `[65, 66, 67]` и ключевого потока `[42, 1, 7]` результат —
`[107, 67, 68]`. Повторное применение тех же ключевых байтов восстанавливает
исходные данные. Поэтому Reader и Writer используют одну операцию.

## Контракт Reader

`Read(p)` возвращает число прочитанных байтов `n` и ошибку `err`.
Данные находятся в `p[:n]`; остальная часть буфера не является результатом.

- Преобразуйте все `n` полученных байтов, даже если вместе с ними пришла ошибка,
  в том числе `io.EOF`. Верните вызывающему коду то же `n` и ту же ошибку.
- Из `prng` нужно получить ровно `n` байтов. Если `n == 0`, ключевые байты
  расходовать не нужно.
- Один вызов Read не обязан заполнить весь переданный буфер. Это относится
  и к данным, и к `prng`. Для получения нужного количества ключевых байтов
  пригодится `io.ReadFull`.
- Не читайте весь вход заранее. Работайте с порцией, запрошенной вызывающим кодом.

## Контракт Writer

- Преобразуйте переданные байты и передайте результат в `w.Write`.
- Нельзя менять исходный `p`, даже временно: сделайте отдельный буфер.
- Верните число записанных байтов и ошибку от `w.Write`, в том числе при частичной
  записи. После ошибки повторных вызовов этой обёртки в тестах не будет.
- При нескольких успешных вызовах поток `prng` продолжается с текущего места,
  а не начинается заново.

## Гарантии и ограничения

- `prng` выдаёт достаточно байтов и не возвращает ошибок. При этом он может
  выдавать меньше запрошенного за один вызов.
- Входные Reader и Writer соблюдают свои контракты. Все аргументы ненулевые;
  параллельных вызовов нет.
- Конструкторы ничего не читают и не записывают: работа начинается при Read/Write.
- Обёртки не закрывают переданные потоки — ими владеет вызывающий код.
- Память на вызов — O(размера переданного буфера), без накопления всего потока.

Реализацию начните в [cipher.go](cipher.go). В тестах `bytes.Buffer` — просто
поток в памяти: в него можно записать байты и затем получить их методом Bytes.

```shell
go test ./04-Interfaces/otp/...
```

Документация: [io.Reader](https://pkg.go.dev/io#Reader),
[io.Writer](https://pkg.go.dev/io#Writer), [io.ReadFull](https://pkg.go.dev/io#ReadFull).
