# yamlembed

Настройте чтение и запись YAML для структур `Foo`, `Bar` и `Baz` из
[types.go](types.go). `Baz` встраивает `Foo` и `Bar`: нужно сохранить данные
обеих частей и разобраться, как их методы влияют на внешний тип.

YAML — текстовый формат для конфигураций. В задаче используется уже добавленная
в проект библиотека `gopkg.in/yaml.v3`. Разбирать YAML вручную не нужно.

## Минимум о библиотеке

`yaml.Unmarshal(data, &value)` заполняет значение из текста, а
`yaml.Marshal(value)` возвращает текстовое представление.
Обе функции возвращают ошибку, если преобразование не удалось.

```go
type Person struct {
    Name string `yaml:"name"`
    Age  int    `yaml:"age"`
}

var p Person
err := yaml.Unmarshal([]byte("name: Ada\nage: 20\n"), &p)
// При err == nil: p == Person{Name: "Ada", Age: 20}.
```

Теги — строки после объявления полей. Нужные в задаче варианты:

- `yaml:"name"` задаёт имя поля в YAML;
- `yaml:"-"` исключает поле из чтения и записи;
- `yaml:"items,omitempty"` не выводит пустой slice;
- `yaml:",flow"` записывает список в виде `[3, data]`;
- `yaml:",inline"` помещает поля встроенной структуры на общий уровень.

## Требуемое поведение

Можно добавлять теги, методы и вспомогательные типы. Имена и типы полей,
а также встраивание `Foo` и `Bar` в `Baz` сохраняйте.

| Поле | При чтении | При записи |
| --- | --- | --- |
| `Foo.A` | ключ `aa` | ключ `aa` |
| `Foo.p` | игнорируется | не выводится |
| `Bar.I` | ключ `i` игнорируется | не выводится |
| `Bar.B` | ключ `b` | ключ `b` |
| `Bar.UpperB` | вычисляется как `strings.ToUpper(B)` | не выводится |
| `Bar.OI` | список `oi` | ключ `oi`, пропускается при nil или пустом slice |
| `Bar.F` | список `f` | ключ `f`, список в формате flow |

`Baz` читает и записывает обе встроенные части без вложенных ключей `foo` и `bar`.
При записи порядок полей: `aa`, `b`, необязательное `oi`, `f`.
В `F` тестируются строки и целые числа. Ошибки декодирования нужно возвращать.
Разбор в тестах начинается с нулевого значения структуры.

Например, вход:

```yaml
aa: hello
p: 42
i: 29
b: world
oi:
- pool
- tree
f:
- 3
- data
```

После чтения `Foo.A == "hello"`, `Bar.B == "world"`, `Bar.UpperB == "WORLD"`;
`p` и `I` остаются нулевыми. Обратная запись:

```yaml
aa: hello
b: world
oi:
    - pool
    - tree
f: [3, data]
```

## Где нужны методы и интерфейсы

Для вычисления `UpperB` одних тегов недостаточно. Библиотека умеет вызывать
методы пользовательских типов через интерфейсы:

```go
type Marshaler interface {
    MarshalYAML() (any, error)
}

type Unmarshaler interface {
    UnmarshalYAML(value *yaml.Node) error
}
```

Внутри `UnmarshalYAML` можно вызвать `value.Decode(&helper)`, чтобы библиотека
заполнила вспомогательное значение. Следите, чтобы это не вызвало тот же метод
по кругу. Отдельный именованный тип и alias ведут себя здесь по-разному.

Не обязательно писать оба метода для каждого типа: используйте теги там,
где их достаточно. После добавления метода `Bar` проверьте отдельно `Baz`:
продвинутый метод получает receiver `Bar`, а не всю внешнюю структуру.

```shell
go test ./04-Interfaces/yamlembed/...
```

После решения объясните: какой метод выбирается для `Baz`, зачем понадобился
вспомогательный тип и почему alias не решает проблему рекурсивного вызова.

Документация: [Marshal и теги](https://pkg.go.dev/gopkg.in/yaml.v3#Marshal),
[Marshaler](https://pkg.go.dev/gopkg.in/yaml.v3#Marshaler),
[Unmarshaler](https://pkg.go.dev/gopkg.in/yaml.v3#Unmarshaler).
