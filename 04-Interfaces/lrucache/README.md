# lrucache

Реализуйте интерфейс `Cache` и конструктор `New(capacity int) Cache`.
Кэш хранит не более `capacity` пар целых чисел. Если место закончилось,
он вытесняет ключ, которым дольше всего не пользовались (LRU).

- `Get` возвращает `(value, true)` для найденного ключа, `(0, false)` для
  отсутствующего. Успешный `Get` делает ключ самым недавно использованным.
- `Set` создаёт или обновляет пару и делает ключ самым недавно использованным.
  Обновление существующего ключа не вытесняет другой ключ.
- `Range` вызывает callback от самого давно использованного ключа к самому
  свежему. `false` останавливает обход. Сам обход порядок не меняет.
- `Clear` удаляет все пары, сохраняя исходную ёмкость.
- При ёмкости 0 конструктор возвращает работающий непустой интерфейс, но `Set`
  ничего не сохраняет. Отрицательная ёмкость приводит к panic.
- Ключи и значения могут быть любыми `int`, в том числе 0 и отрицательными.
- Экземпляры независимы. Потокобезопасность не требуется. Callback не меняет
  кэш и не вызывает его методы; обработку nil callback не проверяем.

Пример: `New(2)` → `Set(1, 10)` → `Set(2, 20)` → `Get(1)` → `Set(3, 30)`.
Ключ 2 вытеснен; порядок `Range` — 1, затем 3.

В этой задаче **O(capacity) на операцию допустимо**.
Достаточно map для значений и slice для порядка. `container/list` и O(1)
можно попробовать самостоятельно после зелёных тестов; дополнительных баллов
за эту оптимизацию нет. Память не должна расти с числом обращений: O(capacity).

Файл `cache.go` задаёт контракт и не меняется. Реализацию начните в `lru.go`.

```shell
go test ./04-Interfaces/lrucache/...
```
