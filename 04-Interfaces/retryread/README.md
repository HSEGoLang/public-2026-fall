# retryread

Клиент хранилища иногда отвечает временной ошибкой. Реализуйте ограниченные
повторы чтения через интерфейс `Client`:

```go
func Read(client Client, key string, attempts int) (string, error)
```

`attempts` — максимальное **общее число вызовов**, а не число повторов после
первого. При `attempts <= 0` верните `("", ErrAttempts)`, не вызывая клиента.

- При успехе верните значение и настоящий nil. Пустая строка тоже успех.
- Обёрнутые `ErrNotFound` и `ErrDenied` окончательны: остановитесь сразу.
- Иначе ищите в цепочке ошибки интерфейс `Temporary` через `errors.As`.
  Повтор допустим только при `IsTemporary() == true` и наличии попыток.
- Любая другая ошибка окончательна. Приоритет окончательных sentinel-ошибок
  выше Temporary, даже если ошибка одновременно реализует этот интерфейс.
- После неудачи возвращайте `("", *AttemptError)`. В нём должны быть исходный
  `key`, фактически использованное число вызовов и точная последняя ошибка.
- Реализуйте `Error() string` и `Unwrap() error` для `AttemptError`. Текст
  содержит ключ, число попыток и сообщение причины; точный формат свободный.
  `errors.Is`/`errors.As` должны проходить к исходной причине.

Все вызовы передают один и тот же ключ. Клиент ненулевой, вызовы последовательны.
Не добавляйте sleep, сеть, goroutines, бесконечные циклы и повтор записи.
При сбое значение, одновременно возвращённое клиентом, не является результатом.

Типы и sentinel-ошибки уже даны в `types.go`; менять этот файл не нужно.
В открытых тестах есть fake, который возвращает заранее заданные ответы.

```shell
go test ./04-Interfaces/retryread/...
```
