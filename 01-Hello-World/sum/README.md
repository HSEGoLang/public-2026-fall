# sum: первая сдача

В этой задаче нужно сложить два числа и освоить отправку решений.

Все команды ниже запускаются **из корня личного репозитория**, где лежат `go.mod`, `Makefile` и каталог `01-Hello-World`. На Windows используйте **Git Bash** из [Git for Windows](https://git-scm.com/install/windows).

## Подготовка — один раз

1. Зарегистрируйтесь в [Manytask](https://app.manytask.org/hse-go-2026-fall/). Откройте **My Repo**: это ваш личный репозиторий, в который нужно отправлять решения.
2. Добавьте [SSH-ключ в GitLab](https://gitlab.manytask.org/-/user_settings/ssh_keys). Инструкция по созданию ключа есть на этой странице.
3. Скопируйте адрес из **Code → Clone with SSH** и склонируйте репозиторий. Замените `USERNAME` своим логином:

   ```shell
   git clone git@gitlab.manytask.org:hse/go/students-2026-fall/USERNAME.git
   cd USERNAME
   git remote -v
   ```

   `origin` должен указывать на ваш репозиторий в `students-2026-fall`. Репозиторий `public-2026-fall` — источник новых условий, решения туда отправлять не нужно.

4. Установите [Go](https://go.dev/dl/). В текущем `Makefile` курса закреплены Go **1.27.1** и golangci-lint **v2.13.2**. После обновления репозитория сверяйте версии с `GO_TOOLCHAIN_VERSION` и `GOLANGCI_LINT_VERSION` в `Makefile`.

   ```shell
   go version
   make setup
   ```

   `make setup` скачивает зависимости и устанавливает линтер в каталог `bin` внутри `go env GOPATH`. Если линтер там уже есть, команда не обновляет его автоматически: проверьте `golangci-lint --version`.

### Если нет make, в том числе на Windows

Устанавливать `make` для сдачи необязательно. Для задач первой лекции достаточно загрузить зависимости корневого модуля:

```shell
go mod download
```

Установите golangci-lint нужной версии по [официальной инструкции](https://golangci-lint.run/docs/welcome/install/).

На macOS/Linux:

```shell
curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b "$(go env GOPATH)/bin" v2.13.2
export PATH="$(go env GOPATH)/bin:$PATH"
```

На Windows используйте **Git Bash**. Скачайте архив для Windows из [релиза v2.13.2](https://github.com/golangci/golangci-lint/releases/tag/v2.13.2), распакуйте `golangci-lint.exe` в каталог `bin` своей домашней папки и выполните в Git Bash:

```shell
export PATH="$HOME/bin:$PATH"
```

Проверьте установку командой `golangci-lint --version`. Чтобы настройка `PATH` сохранялась при открытии терминала, добавьте соответствующую строку `export` в `~/.bashrc` (для zsh — в `~/.zshrc`).

## Решение, форматирование и проверка

Для обычных ДЗ можно работать прямо в **`main`**. Отдельная ветка и merge request для каждой задачи не нужны.

Откройте `01-Hello-World/sum/sum.go` и допишите `Sum`. Сохраните строку `//go:build !solution` и пустую строку после неё. Не меняйте имя пакета, сигнатуру функции, тесты, `go.mod`, `go.sum` и конфигурацию линтера: проверяющая система использует свои версии служебных файлов.

Проверьте решение:

```shell
go test ./01-Hello-World/sum/...
make format 01-Hello-World/sum
golangci-lint run ./01-Hello-World/sum/...
```

Без `make` форматирование выполняют те же две команды:

```shell
golangci-lint run --no-config --enable-only wsl_v5 --fix ./01-Hello-World/sum/...
golangci-lint fmt ./01-Hello-World/sum/...
```

Первая расставляет пустые строки по правилам `wsl_v5`, вторая запускает форматтеры из `.golangci.yml`. Затем снова выполните `go test` и `golangci-lint run` для задачи. Форматирование меняет файлы, а обычный `run` только проверяет их.

Встроенный `gofmt` можно запустить отдельно:

```shell
gofmt -w 01-Hello-World/sum/sum.go
```

Он исправляет базовое оформление Go, но не заменяет все форматтеры и проверки курса. Если линтер продолжает ругаться, прочитайте имя проверки, файл и строку в сообщении. Например, ошибку компиляции или необработанный `error` форматтер не исправит.

Для другой задачи замените `01-Hello-World/sum` её полным путём. Не запускайте `go test ./...` ради одной задачи: незаполненные заготовки остальных ДЗ могут падать.

## Отправка в Manytask

```shell
git status
git diff -- 01-Hello-World/sum/sum.go
git add 01-Hello-World/sum/sum.go
git commit -m "Solve sum"
git push origin main
```

`git add` выбирает файлы для коммита, `commit` сохраняет изменения локально, `push` отправляет их на сервер. Файл с решением должен лежать в каталоге задачи. Для новой посылки нужны изменения в файлах этой задачи, а не только в произвольном README.

**Проверяются задачи, изменённые в последнем коммите.** Если сделать несколько коммитов с разными задачами и один push, проверятся только задачи из последнего коммита. Удобный порядок: решили задачу → commit → push. Несколько задач можно отправить одним общим коммитом.

Откройте **My Submits** в [Manytask](https://app.manytask.org/hse-go-2026-fall/), дождитесь завершения проверки и убедитесь, что баллы появились в [таблице](https://app.manytask.org/hse-go-2026-fall/database). Успешный `git push` означает только доставку кода, а не зачёт задачи.

Если проверка упала, откройте лог задания `grade`. Исправьте причину, снова проверьте задачу локально и отправьте новый коммит. Для повторного запуска **той же посылки** есть кнопка **Retry** на странице проверки в GitLab. Пустой коммит не выбирает задачу для проверки.

## Как получать новые ДЗ и исправления

Обновления забираются из `public-2026-fall`, а ваши решения хранятся в личном `origin`. Rebase переносит ваши коммиты поверх новой версии материалов.

Сначала завершите обычную сдачу: сохраните свои изменения коммитом и отправьте их в `origin`. `git status` должен показывать чистое рабочее дерево. Затем:

```shell
git switch main
make rebase-on-public
```

Без `make` вместо последней команды выполните:

```shell
# Только при первом обновлении:
git remote add public-repo git@gitlab.manytask.org:hse/go/public-2026-fall.git

# При каждом обновлении:
git fetch public-repo
git rebase public-repo/main
```

Если `public-repo` уже существует, повторно добавлять его не нужно; проверьте адрес через `git remote -v`.

Ваши закоммиченные решения переносятся вместе с коммитами. Если преподаватель менял тот же участок файла, Git может попросить разрешить конфликт:

1. Выполните `git status` и откройте перечисленные конфликтующие файлы.
2. Сопоставьте обе версии, сохраните своё решение вместе с нужными обновлениями условия или заготовки, уберите маркеры `<<<<<<<`, `=======`, `>>>>>>>`.
3. Выполните `git add путь/к/исправленному/файлу`, затем `git rebase --continue`. Повторите, если появятся другие конфликты.

Не выбирайте `git rebase --skip` вслепую: он пропускает целый ваш коммит и может убрать решение. Если не уверены, `git rebase --abort` вернёт состояние до начала rebase; после этого можно обратиться за помощью. Не используйте `git reset --hard public-repo/main` для обновления — он отбросит ваши коммиты в текущей ветке.

После успешного rebase проверьте решения и отправьте обновлённую историю:

```shell
git push --force-with-lease origin main
```

Rebase меняет идентификаторы коммитов, поэтому обычный push может быть отклонён. `--force-with-lease` дополнительно проверяет, что удалённая ветка не ушла вперёд относительно известного вам состояния. Если он отклонён, проверьте изменения в `origin`; не заменяйте его на `-f`. Для обычных следующих сдач снова используйте `git push origin main`.

## Если что-то не работает

- `go: go.mod file not found` или каталог задачи не найден: проверьте, что терминал открыт в корне личного репозитория и новые ДЗ уже получены.
- `golangci-lint: command not found`: проверьте установку, `PATH` и версию линтера; наличие Go само по себе не устанавливает линтер.
- Локальные тесты зелёные, а посылка не прошла: проверьте линтер, лог `grade`, отправленную ветку и файлы последнего коммита. На сервере есть дополнительные тесты.
- Нужна помощь: приложите в чат название задачи, выполненную команду, полный текст ошибки и ссылку на посылку. Само решение в общий чат выкладывать не нужно.
