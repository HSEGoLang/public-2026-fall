# parallelmap

В кафе есть несколько бариста. Заказы готовятся независимо, но выдавать
готовые напитки нужно в исходном порядке заказов. Создавать нового бариста
для каждого заказа дорого: число исполнителей ограничено.

Напишите функцию:

```go
func Map(values []int, workers int, f func(int) int) []int
```

Она возвращает новый слайс, где `result[i] == f(values[i])`, и использует
небольшую фиксированную группу рабочих горутин.

Правила:

- `f` вызывается ровно один раз для каждого элемента, в том числе для
  повторяющихся значений. Входной слайс не изменяется.
- Порядок результата совпадает с порядком входа. Порядок запуска и
  завершения вычислений не гарантируется.
- Одновременно работают не больше `workers` вызовов `f`. Если заданий
  хватает, используйте все `workers` исполнителей: последовательное
  решение не подходит. Для короткого слайса достаточно `len(values)` рабочих.
- Создавать отдельную горутину на каждый элемент нельзя. Число горутин
  не должно расти вместе с числом заказов при фиксированном `workers`.
- `Map` возвращается после завершения всех запущенных им работ. Фоновых
  горутин, ожидающих новые заказы, не остаётся.
- При пустом входе верните слайс длины ноль, не вызывая `f` и не запуская
  рабочие горутины. Слайс может быть `nil`.
- При `workers <= 0` функция паникует, даже если вход пустой.

Гарантируется, что для непустого входа `f` не равна `nil`, безопасна для
конкурентных вызовов, завершается и не паникует. Обрабатывать ошибки или
отмену не нужно. Каждый вызов `Map` независим от других.

Пример:

```go
Map([]int{3, 1, 3, 2}, 2, func(x int) int { return x * x })
// []int{9, 1, 9, 4}
```

Используйте каналы для передачи работ и ожидания завершения. Готовые пулы,
`sync`, `sync/atomic` и `golang.org/x/sync` в реализации запрещены.
Не заменяйте ожидание циклом с `default`, `Sleep` или `Gosched`.

Полезно до написания кода ответить на три вопроса: как отличить два
одинаковых заказа, кто закрывает канал заказов и как понять, что все
исполнители закончили? Семинарские потоковые этапы помогут с каналами,
а полный порядок выдачи и ограничение числа исполнителей нужно собрать здесь.

Проверка из корня репозитория:

```shell
go test ./05-Goroutines/parallelmap/...
go test -race ./05-Goroutines/parallelmap/...
```
