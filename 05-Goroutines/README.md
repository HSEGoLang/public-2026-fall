# Горутины и каналы

В основной части четыре задачи по 100 баллов. Три дополнительные задачи
дают бонусные баллы и требуют самостоятельного разбора новых примитивов.

| Задача | Что практикуем | Баллы |
| --- | --- | --- |
| [tour1](tour1/README.md) | Повторение горутин, каналов и `select` | 100 |
| [once](once/README.md) | Один исполнитель и ожидание результата всеми остальными | 100 |
| [waitgroup](waitgroup/README.md) | Счётчик работ, уведомление всех ожидающих, повторное использование | 100 |
| [parallelmap](parallelmap/README.md) | Ограниченное число рабочих горутин и сохранение порядка результатов | 100 |
| [rwmutex](rwmutex/README.md), бонус | Раздельный доступ читателей и писателя | +100 |
| [cond](cond/README.md), бонус | Очередь ожидающих, уведомления и повторная проверка условия | +100 |
| [ratelimit](ratelimit/README.md), бонус | Управляющая горутина, отмена, время и остановка | +100 |

Рекомендуемый порядок — первые четыре строки таблицы. Для основной части
достаточно материала лекции 5 и упражнений семинара. `once` и `waitgroup`
реализуются на каналах: использовать готовые примитивы из `sync` нельзя.
Ограничения остальных задач указаны в их условиях.

Бонусы выходят за рамки основной 80-минутной лекции. Их условия объясняют
дополнительные понятия и дают ссылки; решать их для освоения основной темы
не обязательно.

Команды запускаются из корня репозитория:

```shell
go test ./05-Goroutines/once/...
go test -race ./05-Goroutines/once/...
```

`-race` помогает обнаружить несинхронизированный доступ к памяти. Прошедший
запуск без `-race` сам по себе не доказывает отсутствие гонки.
