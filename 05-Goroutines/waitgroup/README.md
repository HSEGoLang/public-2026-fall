# waitgroup

Нужно дождаться окончания нескольких работ, число которых известно до их
запуска. Реализуйте учебный аналог
[sync.WaitGroup](https://pkg.go.dev/sync#WaitGroup) с помощью каналов:

```go
func New() *WaitGroup
func (wg *WaitGroup) Add(delta int)
func (wg *WaitGroup) Done()
func (wg *WaitGroup) Wait()
```

Экземпляр создаётся через `New()`. Поддержка нулевого значения `WaitGroup`
не нужна. После начала использования объект нельзя копировать.

У объекта есть счётчик незавершённых работ, изначально равный нулю:

- `Add(delta)` изменяет счётчик на `delta`; отрицательный `delta` разрешён.
- `Done()` эквивалентен `Add(-1)`.
- Если счётчик должен стать отрицательным, вызов паникует со строкой
  `"negative WaitGroup counter"`.
- `Wait()` при нуле возвращается сразу. Иначе блокируется до достижения
  нуля. Одновременно ждать могут несколько горутин; освободить нужно всех.
- После завершения всех прошлых `Wait` объект можно использовать для
  новой независимой группы работ.

Первый положительный `Add` новой группы вызывается **до** `Wait` и до
запуска горутин этой группы. Иначе `Wait` вправе увидеть ноль и завершиться.
Пока счётчик положителен, `Add` и `Done` можно вызывать конкурентно.
Новую группу нельзя запускать, пока ещё возвращаются `Wait` прошлой группы.
Эти правила использования гарантируются вызывающим кодом.

Пример использования (это не реализация):

```go
wg := New()
wg.Add(2)
go func() {
    defer wg.Done()
    prepareTea()
}()
go func() {
    defer wg.Done()
    prepareCookies()
}()
wg.Wait() // Чай и печенье готовы.
```

Использование `sync` и `sync/atomic` в реализации запрещено. Ожидающие
горутины должны блокироваться, а не опрашивать счётчик в цикле, спать или
вызывать `runtime.Gosched`. Не оставляйте фоновые горутины после окончания
работы с объектом.

Проверка из корня репозитория:

```shell
go test ./05-Goroutines/waitgroup/...
go test -race ./05-Goroutines/waitgroup/...
```
