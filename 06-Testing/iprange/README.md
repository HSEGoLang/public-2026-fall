# iprange

Найдите и устраните crash в `ParseList` с помощью нативного Go fuzzing.
Добавьте свой `Fuzz*` тест в новый `*_test.go`. Начните с небольшого seed corpus
и вызывайте `ParseList` на произвольных строках. Некорректный ввод может
вернуть ошибку; функция не должна паниковать.

`ParseList` принимает список IPv4-описаний, разделённых запятыми, и возвращает
пары (`Min`, `Max`). Основные формы:

- `10.0.0.1`;
- `10.0.0.0/24`;
- `10.0.0.*`;
- `10.0.0.1-10`.

Пример результата есть в [example_test.go](example_test.go). Сохраните поведение
существующих тестов. Задача не требует переписать готовую грамматику парсера
или расширять набор поддерживаемых форматов. Тестируйте именно `ParseList`:
`Expand` для большого диапазона может потребовать огромный объём памяти.

После обнаружения падения сохраните минимальный ввод как обычный
регрессионный тест или файл Go fuzz corpus. Он должен воспроизводиться
обычным `go test` и после исправления проходить. Не обходите проблему
общим `recover`, который скрывает panic без исправления его причины.

Из корня репозитория:

```shell
go test ./06-Testing/iprange/...
go test -fuzz=FuzzParseList -fuzztime=10s ./06-Testing/iprange
```

Во второй команде подставьте имя собственного fuzz-теста, если оно другое.
Обычный `go test`, в том числе grader, выполняет seed corpus и сохранённые
регрессии. Новые случайные входы генерируются только при запуске с `-fuzz`.
Закрытые регрессионные тесты дополнительно проверяют исправление crash;
имени `FuzzParseList` среди закрытых функций нет.

Справка: [Go fuzzing tutorial](https://go.dev/doc/tutorial/fuzz).
