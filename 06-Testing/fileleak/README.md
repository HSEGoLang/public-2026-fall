# fileleak

Реализуйте библиотеку для поиска незакрытых файловых дескрипторов в тестах.
Единственная функция — `VerifyNone(t)`. Её аргумент поддерживает методы
`Errorf(string, ...interface{})` и `Cleanup(func())`; подходит `*testing.T`.

В начале вызова сделайте снимок открытых дескрипторов процесса.
Через `t.Cleanup` зарегистрируйте повторный снимок в конце теста.
Если в конце есть дескриптор, которого не было в начале, либо тот же номер
теперь указывает на другой target, сообщите об ошибке через `Errorf`.
Закрывать найденные ресурсы библиотека не должна. Ошибку чтения снимка
тоже сообщайте через `Errorf`.

Открытые дескрипторы представлены символическими ссылками в `/proc/self/fd`.
Имя ссылки — номер дескриптора, `os.Readlink` возвращает target: путь,
описание pipe или socket. Храните **номер и target**: два открытия одного
pathname создают разные дескрипторы и тоже могут протекать.

Дескриптор чтения самой директории может исчезнуть между `os.ReadDir`
и `os.Readlink`. Исчезнувшую ссылку можно пропустить; остальные ошибки
нельзя молча игнорировать.

## Cleanup и границы снимков

Вызывайте `VerifyNone` в начале теста. Cleanup выполняются в обратном порядке
регистрации: закрытие ресурса, зарегистрированное позже, произойдёт до проверки.
Закрытые к моменту повторного снимка ресурсы не являются утечкой.

```go
func TestRead(t *testing.T) {
    VerifyNone(t)
    f, err := os.Open("input.txt")
    if err != nil {
        t.Fatal(err)
    }
    t.Cleanup(func() { _ = f.Close() })
    // Проверка чтения из f.
}
```

Снимки относятся ко **всему процессу**, а не к одному тесту или горутине.
Не используйте этот helper в параллельных тестах, пока другие тесты или
фоновые горутины открывают и закрывают дескрипторы. Если runtime или
библиотека впервые создают долгоживущие служебные дескрипторы, выполните
такую инициализацию до `VerifyNone`.

Закрытие и повторное открытие того же pathname с тем же номером дескриптора
между снимками обнаружить таким способом нельзя. Ресурс, который был
открыт и закрыт целиком между снимками, также не является найденной утечкой.

## Запуск

Для выполнения тестов нужен Linux с доступным `/proc/self/fd`.
На macOS/Windows пакет компилируется, но Linux-тесты не запускаются;
успешная компиляция не является проверкой решения. Используйте Linux,
WSL2, контейнер или CI. Например, из корня репозитория:

```shell
go test -count=1 ./06-Testing/fileleak/...
go test -count=1 -race ./06-Testing/fileleak/...
```

Для `-race` нужен включённый CGO и C-компилятор. Контейнер для обычного
Linux-запуска, если Docker установлен:

```shell
docker run --rm -v "$PWD:/work:ro" -w /work golang:1.27-bookworm \
    go test -count=1 ./06-Testing/fileleak/...
```
